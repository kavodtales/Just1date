# Native distribution, installable web and video calls

The requested deliverables are a production web/PWA, a signed Android APK for
direct installation, an Android AAB for Google Play and an iOS build for
TestFlight/App Store review. Existing premium design, real members and isolated
fictional preview sessions must remain intact. No million-user capacity or store
approval is claimed without evidence.

## Implementation order

1. Add migration 011: private call sessions, invitation/acceptance state machine,
   idempotency, bounded duration, member RLS, block/unmatch/account revocation,
   durable media-room cleanup and worker health.
2. Add an authenticated LiveKit provider adapter, short-lived scoped tokens,
   signed webhooks, room cleanup, OpenAPI and SQL/REST tests.
3. Add web/native call invitations, incoming calls, explicit join, microphone and
   camera controls, connection/reconnection/error states and ending calls.
4. Add web manifest, icons, private-data-safe offline fallback, installation UI
   and a distribution page that exposes only verified release artifacts.
5. Configure EAS APK/AAB/iOS builds, public runtime settings, signing boundaries,
   permissions, deep links and release checks. Start real cloud builds using the
   existing authorized Expo account when possible.
6. Verify tests, types, lint, production builds, native bundles, actual artifacts
   and live deployment before recording delivery evidence.

## Media and privacy boundaries

Only members of an active mutual match can invite or join. The recipient must
accept before either party receives a media token. Joining does not secretly
activate camera or microphone. Video is not recorded by this application. LiveKit
is a media processor and must be covered by the approved privacy notice. Do not
claim end-to-end encryption or identity verification that has not been implemented.

Production call access requires a healthy cleanup worker in addition to provider
credentials. This worker enforces expiry and revocation even when clients ignore
the UI. Vercel hosts HTTP APIs, not the long-running media server/worker. A managed
LiveKit project or separately operated deployment is required. Server secrets
never enter web/native public environment variables or client bundles.

## External release dependencies

The existing Expo login is checked without exposing credentials. Apple device
builds require an authorized Developer team and provisioning; Google Play needs
the owner's Console account and store declarations. Video requires provider
configuration. Public signup/recovery still require a verified email sender.
Pending account details do not prevent implementation and local verification.

Progress and measured results will be appended as work completes. An export,
simulator bundle or build configuration is not a signed installable app.
