# Just1date audit and rebuild - 11 November 2026

The existing app was audited, repaired and rebuilt. Live service availability is
recorded separately from automated tests; passing fixture tests does not mean
the production database or its providers are available.

## Findings and repairs

- **Production service outage:** `kyfohngqetzsrqsyabey.supabase.co` returns
  `ENOTFOUND`. The API consequently returns 503 for health/readiness. The owner
  explicitly deferred restoring/resuming Supabase. No live member, messaging,
  date-planning or staff operation can be claimed functional while it is down.
- **Unavailable demo:** added an explicitly opted-in device-only preview when
  the server is unreachable/5xx. It supports fictional profiles, filtering,
  likes/passes, scripted messages and simulated date responses. The banner
  clearly identifies this mode. It never sends real messages, invitations or
  reservations. Activity stays in sessionStorage in the current tab, expires
  within 24 hours and is cleared on exit; blocked storage falls back to memory.
  A server 410 intentionally disabling its demo does not offer this fallback.
- **Silent birthday validation:** registration now explains missing/underage
  birthdays. Passwords have a stable accessible name and length bounds.
- **Misleading recovery success:** web/native recovery now distinguishes
  provider outages and rate limits from account-specific feedback, retaining
  non-enumeration. Native recovery validates email before any provider request.
- **Callback failures:** native callbacks handle rejected/unconfigured service
  requests; the web sign-in screen explains expired links. Unknown auth routes
  return 404. Native `mode=recovery` opens the correct form.
- **Host HTML errors:** member API calls and auth forms show recoverable errors
  for non-JSON responses instead of JSON parser errors or false success.
- **Visual and staff defects:** corrected the clipped mobile logo, loaded
  signed staff-review photos directly and enabled staff navigation only after
  identity loading, preventing clicks from being lost before hydration.
- **Shared validation:** server and device demo actions use the same strict
  schema, with explicit simulated consent. Message/date retries are idempotent;
  conflicting retries, stale revisions and unbounded activity are rejected.
- **Deployment tooling:** removed reliance on a hard-coded Vercel credential
  file. The official CLI now manages login/refresh, and named environment
  variables travel through stdin. Git-connected deployments remain available
  even if the workstation CLI is signed out. Existing settings are preserved.

## Verification

The SQL/API/unit suite passes 85 tests, including outage feedback, device-state
expiry/corruption, message deduplication and date-consent/revision checks. Lint,
workspace typechecks and production web/admin/API builds pass. All 99 applicable
member-browser scenarios and 10 staff-browser scenarios pass across desktop and
mobile sizes, including the repaired regressions. GitHub independently verifies
the build, native exports and browser suites in both repositories. Exact native
artifact verification is recorded in `security/mobile-candidate-2026-11-11.json`.
Browser journeys use isolated fictional fixtures; no live member activity or
email/SMS was fabricated. Three credential-dependent staging journeys remain
skipped while the production backend is unavailable.

The read-only live audit passes 17 of 20 checks: public pages, original photos,
PWA files and unauthenticated member/staff boundaries respond correctly. The
three failures are API health, database readiness and Supabase Auth DNS. See
`docs/security/audit-live-2026-11-11.json`; rerun with:

```powershell
node --use-env-proxy --use-system-ca scripts/audit-live.mjs 2026-11-11
```
